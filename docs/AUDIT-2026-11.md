# Аудит безопасности и корректности — ноябрь 2026

Разбор отчёта по ревью Sprint 31: что подтвердилось, что исправлено, что
осознанно оставлено. Формат: пункт → причина → исправление → статус.

## Критичные

### 1. CSRF-guard проходил из-за OR с `Host`
- **Причина:** `isDashboardRequestTrusted` возвращал `originLoopback || hostLoopback`.
  `Host` — адресат запроса, для локального сервера он всегда loopback, поэтому
  cross-origin POST с `Origin: evil.com` проходил.
- **Исправление:** если заголовок `Origin` присутствует, проверяется только он
  (`Origin: null` отклоняется); `Host` проверяется лишь когда `Origin` нет.
  Разбор host вынесен в `parseLocalHostname` (`127.0.0.1`, `localhost`, `::1`,
  `[::1]`), схема/userinfo/path отбрасываются.
- **Статус:** исправлено, `src/server.ts`.

### 2. GET `/api/*` не были прикрыты (DNS rebinding)
- **Причина:** guard применялся только к `mutationPost`.
- **Исправление:** `needsDashboardSourceCheck()` покрывает все `/api/*` (любой
  метод) кроме `/api/hooks/*`. `/api/export-db`, история, аудит, логи и метрики
  больше не отдаются при `Host: evil.com`. Запросы своего дашборда проходят:
  same-origin `Host` — loopback.
- **Статус:** исправлено, `src/server.ts`.
- **Клиент:** все POST из `renderPage` шлют `X-Scheduler-Client: dashboard`
  (раньше заголовок был только в SECURITY.md).

### 3. Инвертированная полярность эмбеддинг-дедупа
- **Причина:** `if (hit && !isDedupSuppressed(...)) return;` — `isDedupSuppressed`
  возвращает `true` для НЕважных статусов, поэтому подавлялись `error`/`timeout`,
  а `success`-дубликаты проходили.
- **Исправление:** условие `if (hit && isDedupSuppressed(...)) return;` —
  та же полярность, что у rule-дедупа выше.
- **Статус:** исправлено, `src/notifications.ts`.

### 4. Математика эмбеддингов
- **Причина:** вектор строился длиной в число уникальных слов, индекс — порядок
  первого появления. Векторы разных текстов несравнимы позиционно, а
  `embeddingExists` игнорировал `taskName/status`; `INSERT OR REPLACE` по ключу
  `task|status` хранил только последний вектор.
- **Исправление:** feature hashing в фиксированную размерность 512 (FNV-1a,
  знак + `1+log(tf)`, L2-нормализация); косинус требует равной длины; выборка
  `WHERE task_name = ? AND status = ? AND created_at >= ? ORDER BY created_at DESC
  LIMIT 500`; уникальный ключ на вектор (история), `maxVectors` ограничивает
  таблицу. `embedding.enabled` остаётся `false` по умолчанию.
- **Статус:** исправлено, `src/notifications.ts`.

## Помельче

- **Windows stale lock:** в файл пишется PID, порог передаётся параметром
  `-StaleLockMaxAgeMs`; lock мёртвого процесса перехватывается сразу.
- **Quality Gate / pre-flight на Windows:** `Invoke-HookScript` получил таймаут
  (`GateTimeoutSeconds`, код 124), процесс убивается через `taskkill /T`.
- **`Get-UsageFromLog`:** якорные шаблоны формата OpenCode, берётся последнее
  совпадение, строки `opencode.json`/`OPENCODE_CONFIG` пропускаются.
- **`Format-LogLine`:** состояние `inServiceBlock`/`inComment` сбрасывается
  перед каждой попыткой.
- **Дедуп-счётчик:** read-modify-write в `BEGIN IMMEDIATE`.
- **CI:** push в `dev` теперь тоже проверяется.
- **Node:** `engines` и README — `>=22.22` (требование chokidar 6).
- **Версия:** `1.5.5`, CHANGELOG синхронизирован; «бенчмарк» → «бенчмарк».
