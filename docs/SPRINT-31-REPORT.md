## Выполнено в спринте 31

### 31.3 — Саммари уведомлений в три строки

**Модуль `src/core/summary.ts`** — запрашивает у локальной модели строгий JSON `{"lines": [...]}` (1–3 строки, каждая ≤ `maxCharsPerLine` символов) и подставляет их в сообщение Telegram/тоста вместо шаблона.

- Structured output: строгая JSON-схема, валидация через `parseSummary`, очистка код-образок (`stripCodeFence`).
- Fallback на детерминированное усечение (`truncateSummary`) при любом отказе модели: нет провайдера, HTTP-ошибка, таймаут, битый JSON, несоответствие схеме. Уведомление не блокируется и не теряется.
- Настройки: `notifications.summary` (`enabled`, `maxLines` 1..3, `maxCharsPerLine` 20..500, `timeoutMs` 1000..120000, по умолчанию выключено, таймаут 8 с).
- Интеграция в `notifyTaskCompletion`: когда `summary.enabled`, тело уведомления формируется из строк модели (или усечения); иначе — обычный шаблон.
- Тест `test-notifications-summary.mjs` — 9/9: валидный JSON модели, невалидный JSON → усечение, выключенное саммари, недоступный провайдер (доставка не блокируется, < 10 с).

### 31.6 — Счётчик «сэкономлено $»

**Модуль `src/core/savings.ts`** — контрфактика по истории запусков: запуски, потратившие токены, но не записавшие стоимость (локальная модель, подписка), оцениваются по эталонной облачной цене $0.01 / 1k токенов.

- Всегда помечается как `kind: "estimate"` — оценка, а не бухгалтерия.
- Рядом с суммой на дашборде: пометка «оценка» и ссылка на методику `docs/SAVINGS.md`.
- Поле `report.savings` в `get_analytics`: `savedUsd`, `runs`, `tokens`, `actualCostUsd`, `totalCostUsd`, `referenceCostPer1kTokensUsd`, `methodologyUrl`, `byTask`.
- Не учитывает: кеш промптов, скидки, разницу входных/выходных токенов, запуски без токенов.
- Тест `test-savings.mjs` — 14/14 на фиксированных данных (пустая история, контрфактика 3500 токенов = $0.035, оплаченный запуск не считается, своя цена, интеграция с `buildAnalytics`, окно анализа).
- Документация: `docs/SAVINGS.md`, обновлены `docs/FEATURES.md`, `README.md`, `CHANGELOG.md`.

### 31.5 — Кнопка «Сравнить» (before/after)

**Модуль `src/core/triage-compare.ts`** — пргоняет одно событие уведомления под двумя наборами настроек триажа (before/after) и возвращает diff вердиктов, правил, уверенности, категории, причин и итоговых сообщений.

- RPC-метод `compare_triage` + схемы в `src/rpc.ts`, обработчик в `src/index.ts`.
- Чистый модуль (без БД/HTTP), легко тестируется.
- Тест `test-triage-compare.mjs` — 17/17: подавление правила, fallback llm, одинаковые настройки без diff, все поля diff присутствуют.

### 31.4 — GUI мастер настройки (три экрана)

Мастер доступен из панели «Локальный ассистент» (кнопка «Мастер настройки триажа»).

- Экран 1: выбор поставщика (Ollama / OpenAI-совместимый API) и модели, пояснение последствий отказа модели (уведомления всё равно доставляются).
- Экран 2: пресеты Minimal (только правила) и Recommended (правила + локальная модель).
- Экран 3: порядок срабатывания правил триажа (8 встроенных правил), порог уверенности `confidenceThreshold` с формулировкой «порог перехода к правилам», а не «фильтр уведомлений».
- По кнопке «Завершить и применить» настройки сохраняются через `persistSettings` (RPC `save_settings`).
- Работает без документации: все тексты на экранах, подсказки у полей.
- i18n: ключи `localAi.wizard.*` добавлены в `locales/ru.json` и `locales/en.json`.
