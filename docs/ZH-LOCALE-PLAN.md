# План: интерфейс локали `zh` (locales/zh.json)

**Цель:** полноценная китайская локаль интерфейса планировщика — `locales/zh.json`,
подключённая к `src/i18n.ts` и GUI-бандлу, с паритетом ключей и зелёными тестами.

**Текущее состояние:** `locales/ru.json` (70 286 Б) и `locales/en.json` (51 490 Б) —
по 772 ключа, паритет полный. `zh.json` отсутствует. `Locale = "ru" | "en"`,
`SUPPORTED_LOCALES = ["ru", "en"]`, `DEFAULT_LOCALE = "ru"`.

**Механика i18n (важно для перевода):**
- Ключи плоские, `"gui.job.runTitle"`; значения — только непустые строки.
- ICU-подмножество: `{name}` — подстановка; `{count, plural, one {…} other {…}}`.
- Плюральных ключей 4: `common.runsCount`, `gui.dryRunMatrixPreview`,
  `gui.job.watchGlobsCount`, `gui.matrixWillCreate`. Для `zh` у `Intl.PluralRules`
  есть единственная категория `other` → в китайском каталоге ветка должна быть
  только `other` (ветки `one/few/many` не нужны и будут мёртвым кодом).
- Параметры подстановки — 245 ключей; набор `{…}` обязан совпадать с `en.json`
  (иначе в UI останутся «сырые» плейсхолдеры).
- Fallback: отсутствующий ключ → `ru` → сам ключ. Частичный `zh.json` безопасен,
  но до полного паритета интерфейс будет смешанным (zh + ru).

**Точки интеграции:**
- `src/i18n.ts`: тип `Locale`, `SUPPORTED_LOCALES`, комментарии контракта.
- `src/gui.tsx` (строки 8–12): JSON-импорт каталогов и `registerCatalog` —
  в webview нет доступа к файлам пакета, без импорта `zh` не заработает в GUI.
- `test-i18n.mjs`: проверки контракта, `availableLocales()`, паритета, плюрализации.
- `test-docs.mjs`: проверяет каталоги `ru`/`en`; `zh` не ломает, но паритет
  `zh` нужно добавить в финальный контроль.
- `scripts/test-locale.mjs`: сейчас пропускает только `ru`/`en`.
- `package.json` → `files` уже содержит `locales`, правок не требует.
- `gui-experimental.cjs` — артефакт сборки (`npm run build:gui`).

**Источники терминологии:** `docs/README.zh.md`, `docs/FEATURES.zh.md`,
`docs/FAQ.zh.md`, `docs/CROSS_PLATFORM.zh.md` (готовый китайский глоссарий продукта).

**Правила перевода**
1. Источник истины — `en.json`; `ru.json` — смысловой эталон (в нём есть нюансы).
2. Технические токены не переводятся: `cron`, `JSON`, `SQLite`, `MCP`, `DAG`,
   `HMAC`, `URL`, `ID`, `GUI`, `OpenCode`, `Telegram`, `Ollama`, `glob`, имена
   инструментов (`schedule_task` и т.п.), ключи конфигурации, `${secret:NAME}`.
3. Плейсхолдеры `{…}` копируются дословно и в том же количестве.
4. Пунктуация — полноширинные знаки для китайского предложения (`，` `。` `：`),
   но `…` в конце обрезанных строк и типографские кавычки сохраняют смысл.
   Кавычки вокруг имён — `“…”` или прямые, единообразно по всему файлу.
5. Единый стиль: краткие подписи полей — без точки; предложения — с `。`;
   ошибки и предупреждения — законченные предложения.

## 6. Риски и ограничения

- **Смешанный язык до S18.** Пока каталог неполон, недостающие ключи падают в `ru`
  (fallback). Это ожидаемо и не является дефектом.
- **GUI-строки в `gui.tsx` не все через `t()`** (часть текста дашборда остаётся
  русской по дизайну, см. `docs/README.zh.md`). Задача — каталог, а не рефакторинг
  всех литералов.
- **Длина строк.** Китайский компактнее, но кнопки/бейджи с `white-space:nowrap`
  могут требовать визуальной проверки — отметить в S22, не блокирует каталог.
- **Плюрализация.** `zh` не имеет `one/few/many`; если оставить русские ветки,
  `Intl.PluralRules` их не выберет — это скрытая ошибка, поэтому ветка только `other`.
- **Порядок ключей.** `zh.json` держим в алфавитном порядке (детерминированные
  срезы, стабильные диффы); функционально порядок не важен.
- **`auto` и серверный рендер (T7).** Серверный процесс не видит `ctx.locale`,
  поэтому при `auto` он использует `uiLocale` — последнюю локаль, присланную
  открытым окном. Если окно ещё не открывалось (например, после перезапуска
  OpenCode без GUI), уведомления и дашборд остаются на `ru`; это осознанный
  fail-open до появления серверного источника языка.
- **`direction()` не используется.** Для `ru`/`en`/`zh` всегда `ltr`; RTL-локали
  в плане не заявлены. При добавлении арабского/иврита направление нужно будет
  прокинуть в `dir` панели и дашборда.
- **Селектор языка.** Отдельного экрана «Settings → Language» в GUI-панели нет:
  переключатель живёт в шапке панели планировщика; документация приведена
  в соответствие (S24).
