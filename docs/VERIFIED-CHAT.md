# Верифицированный чат (S-5, Деталь 3.19)

Ответ чата выдаётся пользователю **только** если к нему приложено проверяемое
доказательство. Без доказательства — вежливый отказ, и текст ответа не попадает
ни в результат, ни в CLI-вывод. Это политика «respond only with proof», а не
попытка заставить модель быть честной по обещанию.

Публичный API: `verifyChatAnswer(input, options?)` из `agent-steward/core`
(исходник — `src/core/verified-chat.ts`). Модуль чистый: не читает БД, диск,
сеть, не запускает команды и не импортирует `@opencode-*`.

## Формат решения

```json
{
  "kind": "verified-chat",
  "version": "1.0",
  "format": "agent-steward.verified-chat",
  "methodologyUrl": "https://github.com/DeadSno/agent-steward/blob/main/docs/VERIFIED-CHAT.md#methodology",
  "delivered": true,
  "answer": "Ответ, который можно показать",
  "refusal": null,
  "accepted": { "gates": 1, "sources": 0, "recipes": 0 },
  "evidenceCount": 1,
  "reasons": []
}
```

| Поле | Смысл |
| --- | --- |
| `delivered` | `true` только при выдаче ответа |
| `answer` | Текст ответа или `null` при отказе |
| `refusal` | Причина отказа или `null` |
| `accepted.gates` | Принятые объективные гейты |
| `accepted.sources` | Принятые ссылки на источники |
| `accepted.recipes` | Принятые gate-passed рецепты (S-4) |
| `evidenceCount` | Сколько доказательств было предъявлено |
| `reasons` | Почему доказательства приняты/отвергнуты; пусто при успехе |

## Виды доказательств

### `gate` — объективный гейт

```json
{
  "kind": "gate",
  "source": "test-open-spec.mjs",
  "command": "node test-open-spec.mjs",
  "passed": true,
  "objective": true,
  "recordedAt": "2026-11-24T10:00:00.000Z",
  "commit": "9db0d75"
}
```

Принимается только `passed: true` **и** `objective: true`, с непустыми
`source`/`command`, корректной ISO-датой и (если указан) hex-коммитом от 7
символов. Это самый сильный вид доказательства: решение вынесено кодом.

### `source` — ссылка на источник

```json
{
  "kind": "source",
  "source": "docs/OPEN-SPEC.md",
  "locator": "#methodology",
  "quote": "Дословная цитата, на которой основан ответ.",
  "checkedAt": "2026-11-24T10:05:00.000Z"
}
```

Требует путь/URL, якорь или номер строки, дословную цитату и ISO-дату проверки.

### `recipeId` — gate-passed рецепт

Если указан `recipeId`, вызывается `verifyRecipe()` из библиотеки S-4. Рецепт
считается доказательством только когда его YAML валиден, а объявленные гейты
имеют объективные подтверждения. Пример: `recipeId: "open-spec"`.

## Политика отказа

- нет ни одного принятого доказательства — отказ;
- **любое** предъявленное доказательство невалидно — отказ целиком (частичной
  веры непроверенному нет);
- `objective: false` (самооценка модели) доказательством не считается;
- неизвестный вид доказательства, пустой рецепт, битой даты или неверный
  коммит — отказ;
- `options.minEvidence` (по умолчанию `1`) задаёт порог числа принятых
  доказательств; некорректное значение — ошибка валидации.

При отказе `answer` равно `null`, а причина comes из первого `reasons`. В CLI
причина печатается в `stderr`, а текст ответа не печатается вообще.

<a id="methodology"></a>

## Methodology / методика

1. Формулируется ответ и перечисляются доказательства, на которых он основан.
2. Каждое доказательство проверяется по форме и по объективности (гейт),
   либо по наличию пути/якоря/цитаты (источник), либо через `verifyRecipe()`.
3. Если все доказательства приняты и их число не меньше порога — ответ
   отдаётся; иначе — мотивированный отказ без текста ответа.

### Честные ограничения

- Верификатор **не перечитывает источник** и не доказывает, что цитата
  действительно есть в файле по указанному якорю. Он проверяет структуру
  доказательства. Это ответственность вызывающей стороны; для жёсткой проверки
  используйте объективный гейт с командой.
- Доказательство — снимок на дату `recordedAt`/`checkedAt`, а не гарантия, что
  код с того коммита всё ещё актуален.
- Рецепт из S-4 проверяется по зафиксированным доказательствам, а не
  повторным прогоном его гейт-команды.
- Модуль не вызывает модель и не знает, правдив ли текст ответа по существу:
  он проверяет наличие и качество **обоснований**, а не семантику.

## CLI

```bash
agent-steward chat verify answer.json --json
agent-steward chat verify answer.json
```

Exit-коды: `0` — ответ выдан, `1` — отказ/битые данные, `2` — неверные
аргументы. Файл — JSON-объект с полями `answer`, `evidence` и необязательным
`recipeId`.
