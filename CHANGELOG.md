## [Unreleased]

### Added

- **Идемпотентные ключи шагов (Sprint 36.3):** `src/db/step-idempotency.ts` (`runStepOnce`/`runStepOnceAsync`) — повторный вызов с тем же ключом возвращает сохранённый результат без побочных эффектов; `SCHEMA_VERSION = 4` добавляет частичный уникальный индекс `idx_run_steps_key_unique` с дедупликацией старых ключей.
- **DLQ (Sprint 36.4):** `src/db/run-dlq.ts` — детерминированно упавшие шаги попадают в очередь `run_dlq` (`SCHEMA_VERSION = 5`), доступны список, ручной retry с переоткрытием запуска и discard; вложенные транзакции работают через `SAVEPOINT`.
- **Роутер, слой 1 (Sprint 36.5.a):** `src/core/router/rules.ts` — таблица «тип задачи → транспорт + исполнитель» с нормализацией типа (`Run Tests` → `run_tests`). Модуль не импортирует ни БД, ни модель, ни транспорт: горячий путь стоит 0 токенов, неизвестный тип передаётся слоям 2–3.
- **Роутер, слой 2 (Sprint 36.5.b):** `SCHEMA_VERSION = 6` и таблица `capability_map`; `src/db/capability-repo.ts` учится на исходах гейта (`success_rate`, скользящие средние стоимости/времени, последние 10 исходов) и выбирает `local` / `cloud` / `review` по порогам без модели. Данных меньше трёх исходов — решение `explore`, его принимает слой 3.
- **Роутер, слой 3 (Sprint 36.5.c):** `src/core/router/planner.ts` — декомпозиция миссии: модель вызывается один раз на миссию и только чтобы вернуть шаги с типами, без модели работает эвристика по ключевым словам. Шаг несёт `stepName` и `taskType`, маршрут по-прежнему выбирают слои 1–2; незнакомые типы собираются в `ambiguousTaskTypes`.
- **Эскалация при провале гейта (Sprint 36.5.d):** `src/core/router/escalation.ts` — `escalateAfterGate` поднимает шаг по таблице `local → cloud → review → blocked` по одному флагу `passed`, без БД и модели; `escalationChain` и `isEscalationExhausted` описывают всю цепочку. Сборка маршрута — `src/core/router/dispatch.ts` (`routeStep`: слой 1 → слой 2, `review`/`explore` без транспорта).
- **Маршрутизация без модели (Sprint 36.5.e):** `test-router-dispatch.mjs` доказывает, что известные типы решаются статикой до инициализации БД, статика не пишет в `capability_map`, а `dispatch.ts` не импортирует `planner`; 1000 маршрутов укладываются в миллисекунды.
- **Ночной chaos-тест DAG (Sprint 36.5):** `test-chaos-dag.mjs` убивает `SIGKILL` дочерний процесс посреди цепочки шагов и проверяет, что durable-состояние переживает крах: завершённые шаги остаются `passed`, прерванный шаг восстанавливается с `attempt + 1`, resume доводит запуск до `passed`, `PRAGMA integrity_check` возвращает `ok`. Ночной workflow `.github/workflows/nightly.yml` гоняет сценарий по расписанию на Windows и Ubuntu; локально — `npm run test:chaos`.
- **DLQ в GUI (Sprint 36.6):** панель «♻️ Dead-letter queue» в `src/gui.tsx` показывает открытые записи с причиной, ошибкой и числом попыток; фильтр `open`/`all`/`retried`/`discarded` и счётчик открытых. RPC `list_dlq`/`retry_dlq`/`discard_dlq` работают через фасад `src/core/dlq-api.ts`; retry переоткрывает запуск и готовит шаг к выполнению (`attempt + 1`), discard закрывает запись, не меняя статус шага; мутации пишутся в аудит (`dlq.retry`, `dlq.discard`).

## [0.0.3] - 2026-11-17

### Added

- **Durable run state (Sprint 36.1):** таблицы `runs` и `run_steps` хранят запуск и каждый шаг DAG (`status`, `attempt`, `idempotency_key`, timestamps, `output_json`), переживают перезапуск и падение процесса. `run_steps` каскадно удаляются вместе с запуском; недопустимые переходы отсекаются `InvalidTransitionError`. Схема поднимается до `SCHEMA_VERSION = 3` автоматически, включая старые БД (`PRAGMA user_version`).
- **Журналирование переходов (36.1.b):** `src/db/run-journal.ts` коммитит `running` до выполнения тела шага и `passed`/`failed` после; при `kill -9` в БД остаётся `running` с номером попытки, а `recoverInterruptedSteps()` помечает его `failed`, сохраняя `attempt`. SQLite работает в WAL с `synchronous = NORMAL`.
- **Resume с середины (36.2):** `src/db/run-resume.ts` продолжает цепочку с первого незавершённого шага (`findResumeStep`), пропускает уже пройденные шаги без вызова обработчиков, проверяет наличие всех обработчиков до побочных эффектов и переоткрывает упавший запуск (`reopenRun`). Колонка `run_steps.position` фиксирует порядок шагов (миграция v3 бэкфиллит её из `rowid`).

### Changed

- **Шим `opencode-windows-scheduler@1.5.8`:** тонкий реэкспорт `agent-steward`; зависимость ослаблена до `>=0.0.2`, чтобы шим ставился с любой актуальной версией ядра.
- **Release-workflow:** матрица `verify` сокращена до windows/ubuntu. macOS по-прежнему проверяется обычным CI на каждом push; в релизе он не дублируется, потому что очередь macOS-раннеров блокировала `publish`.

### Deprecated

- **`opencode-windows-scheduler@1.5.7`:** помечен через `npm deprecate` — используйте `agent-steward@>=0.0.2`.

## [1.5.6] - 2026-11-17

### Added

- **Интерфейс на китайском (`locales/zh.json`):** полный перевод всех 772 ключей интерфейса (`gui.*`, `matrix.*`, `shadow.*`, `schedule.*`, `notify.*`, `tool.*`, `localAi.*`, `server.*`, `gitTrigger.*`, `dryRun.*`, `app.*`, `common.*`) с паритетом ключей и плейсхолдеров к `en.json`/`ru.json`; вместе с 5 ключами селектора языка — 777. - **Режим языка `auto` (T7):** `locale: "auto"` следует за языком интерфейса OpenCode. GUI читает `ctx.locale.locale()`, маппит BCP 47 (`zh-CN`/`zh-Hans` → `zh`, `en-GB` → `en`, `ru-RU` → `ru`) и переключает панель без перезапуска; селектор языка (🌐 Авто / Русский / English / 中文) появился в шапке панели. Серверный процесс языка окна не видит, поэтому GUI присылает разрешённую локаль в новом поле `uiLocale` — уведомления, дайджест, результаты инструментов и дашборд используют её. Старые настройки `ru`/`en` читаются без миграции.
- **OpenCode V1 и V2 в одном пакете:** default export объединяет V2 `setup()` и V1 `server()`, поэтому один и тот же пакет работает на V1 ≥ 1.18.29 и V2 ≥ 2.2.7. Обе линии поднимают общее ядро `createRuntime` (SQLite, recovery, watchers, триггеры) и используют один сценарий выгрузки `createShutdownHandler`. Границы и матрица поверхностей — в `docs/COMPATIBILITY.md`; ключ конфига зависит от линии (`plugin` для V1, `plugins` для V2).
- **26 инструментов агента в V1:** `createV1Tools` собирает их из тех же декларативных `createToolSpecs`, что и V2, с общим аудитом `withAudit` и конвертацией результата `Tool.Result` → V1 `ToolResult`. У V1 нет `options.codemode`, поэтому инструменты вызываются обычным способом; GUI-панель и RPC-методы в V1 недоступны, потому что этих subpath в V1 SDK нет.
- **TUI-панель на обеих линиях:** добавлен `src/tui-v1.tsx` — маршрут `/scheduler`, снимок в `sidebar_content`, команды палитры и клавиши, выбор задачи в `api.kv`, обновление раз в 5 секунд. `src/tui.tsx` теперь отдаёт `{ ...v2Tui, tui: tuiV1 }`, а `exports["./tui"]` наконец объявлен в `package.json` — до этого V2 TUI из пакета не загружался вовсе.
- **Тесты совместимости:** `test-dual-entry.mjs` сверяет форму export, наборы имён V1/V2 и кросс-версию zod; `test-v1-integration.mjs` вызывает реальный `server()` с изолированными HOME и портом дашборда; в CI появились отдельные jobs `compat-v1` (V1 SDK 1.19.x) и `compat-v2` (V2 SDK 2.3.0).

Генерируется новый `sessionId`, сохраняется в БД и в sidecar-файл `<task>.session` рядом с оболочкой; bash- и PowerShell-обёртки читают актуальный ID из sidecar перед запуском `opencode run --session`.

## [1.5.5] - 2026-11-16

### Security

- **Политика прав задач (`permissions.ts`):** вместо разрозненных `defaultPermissions` в обёртках появился единый резолвер `src/core/permissions.ts`, а в настройках — `permissions.defaultPolicy` (`hybrid` по умолчанию, `secure`, `legacy`). `hybrid` разрешает read/edit/glob/grep/subagent/skill/webfetch/websearch и **запрещает `shell` и `question`**: задачи идут с `opencode run --auto`, поэтому команды включаются только явным `allowedTools`, флагом задачи `legacyShell` (действует только в `hybrid`) или политикой `legacy`, возвращающей поведение 1.5.x. `secure` оставляет только read/glob/grep/skill. `deniedTools` выигрывает всегда, непустой `allowedTools` превращается в allowlist и может вернуть действие, запрещённое политикой. Конфиг передаётся обёрткам через `OPENCODE_CONFIG_CONTENT`, `opencode.jsonc` не создаётся; отказы политики пишутся в аудит как `tool.blocked` с `reason: "default-policy"`, а обёртки логируют `policy=…, denied=…`. `test-permissions-policy.mjs` — 28 проверок.
- **Дашборд: `X-Scheduler-Client` больше не обходит проверку Origin (server.ts):** `isDashboardRequestTrusted` проверяет `Origin` первым, кастомный заголовок стал лишь дополнительным подтверждением, поэтому подделанный `X-Scheduler-Client: dashboard` с чужого Origin (ошибка CORS, XSS на странице дашборда) больше не открывает `/api/*`. Запросы без `Origin` по-прежнему требуют локальный `Host`, `Origin: null` и чужие схемы отклоняются. `test-dashboard-trust.mjs` — 10 проверок.
- **ACL ключа секретов на Windows (secrets.ts):** `icacls <файл> /inheritance:r /grant:r <пользователь>:F` — `secrets.key` больше не наследует права каталога и доступен только текущей учётной записи (`DOMAIN\user`); при чтении старый ключ получает ACL повторно, то есть ключи, созданные до 1.5.5, мигрируют автоматически. Сбой `icacls` не ломает работу, но один раз пишется в лог. `test-secrets.mjs` — 45 проверок, включая фактические ACE файла.
- **Path traversal в обёртках (ps-wrapper.ts):** `sanitizeName` вызывается внутри `writePromptFile` и `lockFilePath`, а не только на входе инструментов, поэтому имена вида `../../evil`, `..\..\evil`, `/etc/passwd`, `a/b/c` не выводят prompt и lock за пределы `PLUGIN_DIR`. `test-path-safety.mjs` — 13 проверок.
- **CSRF и DNS-rebinding (server.ts):** guard больше не полагается на `Host` при наличии `Origin` — cross-origin POST с `Origin: evil.com` отклоняется. Проверка распространена на все `/api/*` GET (кроме `/api/hooks`), поэтому rebinding больше не читает `/api/export-db`, историю, аудит и логи. Дашборд-клиент шлёт `X-Scheduler-Client: dashboard` во всех POST.
- **Подпись hook-запросов:** при `requireSignature` и ненулевом допуске времени `X-Scheduler-Timestamp` обязателен и входит в HMAC (`<timestamp>.<body>`), поэтому перехваченный запрос нельзя переиграть со свежим timestamp.
- **Секреты:** битый `secrets.json` карантинится в `secrets.json.corrupt-<ts>` вместо молчаливого затирания при следующей записи; отсутствующая ссылка `${secret:NAME}` остаётся литералом и попадает в `missing`.
- **Баш-обёртка:** промпт больше не передаётся через argv-массив с пустым `${arr[@]}` (bash 3.2); `log()` определён до первого вызова; watchdog убивает сам `opencode`, а не subshell; lock хранит PID и перехватывается только у мёртвого процесса; gate/hooks ограничены таймаутом.
- **Windows:** lock пишет PID, stale-порог передаётся параметром; Quality Gate и pre-flight получили таймаут; размер промпта проверяется до создания задачи; убраны отладочные `console.log` аргументов schtasks.

### Fixed

- **Дедуп по эмбеддингам:** исправлена инвертированная полярность (подавлялись именно важные статусы), вектор стал fixed-dimension feature hashing с L2-нормализацией, сравнение — только по одному task+status с историей векторов, а не `INSERT OR REPLACE`.
- **Счётчик дедупа** обновляется в транзакции `BEGIN IMMEDIATE` — гонка между процессами устранена.
- **Git-триггер:** ошибка `git diff` больше не выглядит как «изменений нет» (статус `error`, состояние не продвигается); glob-экранирование веток включает `[` и `]`.
- **Telegram:** сообщения делятся на чанки ≤4096 с учётом surrogate pairs, 429 обрабатывается с `retry_after`.
- **Linux:** расширенные cron-выражения уходят в минутный опрос с gate; ошибка чтения crontab больше не приводит к затиранию пользовательских заданий; блок crontab привязан к профилю.
- **schtasks:** код 1 больше не означает «задач нет»; pause/resume не глотают «задача не найдена»; добавлены локали-алиасы DE/FR/ES/IT/PL.
- **`*/N`:** преобразуется в schtasks только при `60 % N === 0`, иначе poll+gate; `previousRunTime` выравнивается по границе часа.
- **Триаж-воркер:** не более двух одновременных процессов, очередь дренируется освободившимся воркером, старые задания и слоты чистятся.
- **native-notify:** `notify-send` получает `--` перед текстом.
- **Документация:** синхронизированы числа инструментов/тестов/рецептов, Node ≥22.22, IANA-таймзоны; исправлено «ベンчмарк».

### Added

- **Счётчик «сэкономлено $» (Спринт 31.6):** `get_analytics` и дашборд показывают KPI «Сэкономлено» — контрфактику по истории: запуски, которые потратили токены, но не записали стоимость (локальная модель, подписка), оцениваются по эталонной облачной цене $0.01 за 1k токенов. Рядом стоят пометка «оценка» и ссылка на методику `docs/SAVINGS.md`; в отчёте появилось поле `report.savings` (`savedUsd`, `runs`, `tokens`, `byTask`). `test-savings.mjs` — 14 проверок на фиксированных данных.
- **Сравнение триажа «до/после» (Спринт 31.5):** RPC-метод `compare_triage` и модуль `src/core/triage-compare.ts` прогоняют одно событие под двумя наборами настроек и возвращают diff вердиктов, правил, уверенности и сообщений. `test-triage-compare.mjs` — 17 проверок.

- **Семантический дедуп по эмбеддингам (Спринт 31.1):** `notifications.embedding` (`enabled`, `suppressDuplicates`, `windowMinutes`, `threshold`, `maxVectors`) добавляет к точному дедупу сравнение похожести сообщений. Сообщение превращается в нормализованный bag-of-words вектор, векторы лежат в SQLite-таблице `notification_embeddings`, сравнение — косинусом брутфорсом по окну, без новых зависимостей и без внешней модели эмбеддингов. При совпадении выше `threshold` (по умолчанию 0.85) неважное уведомление подавляется; статусы из `importantStatuses` доставляются всегда. - **`runWhenLoggedOff` в экспорте/импорте задач (27.5.10):** поле mode входа теперь сохраняется в экспортный JSON (`buildExportJson`) и читается при импорте (`parseImportJson`), RPC `import_tasks` прокидывает его в `schedulerCreateTask` вместе с `paused`. ### Fixed

- **Откат частично созданной матрицы (27.5.7):** разворачивание матрицы выполняется в общем `try` — ошибка любого клона (лимит длины имени schtasks, отказ ОС, неизвестный workspace) прерывает прогон и удаляет всё, что успело появиться: созданные в этом прогоне клоны (вместе с определениями, очередью и файлами обёртки), агрегатор и — для новой задачи — сам родитель. Раньше сбой второго клона оставлял в планировщике первого клона, а в БД — родителя с половиной семьи. Сообщение называет клон и workspace, например `Не удалось развернуть матрицу "…": клон "…" (workspace "…"): … Созданные клоны удалены.`
- **`update_task` откатывается при сбое (27.5.6):** обновление по-прежнему пересоздаёт задачу (delete + create), но теперь перед удалением запоминается определение из БД и отслеживается факт удаления. Если удалить старую версию не удалось — возвращается `restored: true` с пояснением, что прежняя задача не тронута. Если старая версия удалена, а создать новую не вышло (некорректный cron, нет прав на `/ru SYSTEM`, ошибка ОС), возможный частичный результат удаляется, задача пересоздаётся из сохранённого определения (`recreateTaskFromDefinition`), триггеры пересобираются, а ответ содержит `success: false` и `restored: true` с исходной причиной. Если не удалось и восстановить — `restored: false` и явное сообщение, что задачу нужно создать заново.
- **`update_task` больше не снимает паузу (27.5.8):** бессрочная пауза теперь хранится в определении задачи (`paused: true`) и участвует в экспорте/импорте, поэтому пересоздание задачи при обновлении регистрирует её в ОС и сразу снова ставит на паузу (для матрицы — на клонах). Если пауза не восстановилась, задача всё равно создаётся, а причина пишется в лог. `update_task`, `list_tasks` и RPC `get_tasks` отдают `paused` из определения, ОС или `pausedUntil`, а `resume_task` и авто-возобновление сбрасывают флаг.
- **Безопасные имена задач (hotfix 1.5.1, 27.5.5):** `schtasks` вызывается через `execFile` без `cmd.exe`; имена валидируются до записи в БД (буквы/цифры/пробел/точка/`_`/`-`), а после `/create` плагин проверяет наличие задачи в ОС и при провале удаляет wrapper/prompt/лог и не сохраняет определение.
- **`nextRun` сразу после мутации (27.5.2):** `schedule_task`, `update_task`, `pause_task` и `resume_task` возвращают `nextRun`, рассчитанный из cron/`runAt`/окна (`computeTaskNextRun`), не дожидаясь обновления `schtasks`. `list_tasks` и RPC `get_tasks` используют тот же расчёт, поэтому GUI/дашборд больше не показывают `nextRun: null` сразу после `resume_task`; при паузе отдаётся `paused: true` и `nextRun: null`, для `pause_task until` — `pausedUntil`.
- **`list_tasks` без ложного пустого списка (27.5.3):** при пустом ответе ОС сразу после мутации выполняется один retry (300 мс). Если ОС по-прежнему пуста или недоступна, `list_tasks` отдаёт состояние из БД с `osAvailable:false`, `osError` и задачами `orphaned:true`, а не `[]`; то же состояние возвращает RPC `get_tasks`, дашборд продолжает работать на данных БД.
- **`logonMode` в `list_tasks` (27.5.4):** `schtasks /query` вызывался без `/v`, поэтому ОС не отдавала «Режим входа» и поле всегда было `null`; добавлен `/v` и маппинг русского ключа «Режим входа в систему». Теперь `list_tasks`, GUI и RPC `get_tasks` показывают фактический режим (`Только интерактивный` / фоновая задача SYSTEM).
- **Очистка файлов при удалении (27.5.1):** `delete_task` удаляет wrapper, prompt, лог, lock и env-файлы; при старте плагин вычищает осиротевшие wrapper-ы (с логом `wrappers.cleaned`); повторный `delete_task` идемпотентен, включая русскую ошибку schtasks «Не удается найти».
- **GUI в webview OpenCode:** каталоги `locales/*.json` теперь встраиваются в бандл на этапе сборки (`registerCatalog`). Раньше загрузчик не находил файлы пакета внутри webview, и панель показывала сырые ключи `gui.*` вместо текста.
- **GUI: подписи дней недели** — чипы использовали несуществующие ключи `gui.weekdayShort.*`, из-за чего отображались как есть; теперь `gui.weekday.*` (Пн…Вс / Sun…Sat).
- **GUI: свёрнутые карточки** больше не сжимаются до 2 px в короткой панели (`flex-shrink: 0` у секций), шапки уведомлений/истории/аудита/workspace всегда видны; шапка формы переносится на узких экранах.
- **Веб-дашборд:** длительности в истории и What-If показываются человекочитаемо (`3.5 мин` вместо `212000 мс`), стоимость — с двумя знаками после запятой, у матрицы подпись `❌ ошибок: N` вместо безымянного числа, нулевые значения не засоряют график, KPI укладываются в одну строку, таблицы аналитики не слипаются на узких экранах, первая колонка таблицы задач закреплена и полоса прокрутки видна, текст в узлах DAG не вылезает за рамки.

## [1.5.0] - 2026-11-14

### Profiles (Спринт 21)

- Профили (`default`, `work`, …): каждый профиль — отдельная директория со своей БД (`scheduler.db`), настройками (`settings.json`), логами, обёртками и портом дашборда. `default` использует базовую директорию плагина (как раньше — без миграции), остальные живут в `<base>/profiles/<name>`.
- `OPENCODE_SCHEDULER_PROFILE` > файл-маркер `active-profile` > `default`; переключение требует перезапуска OpenCode. Порт дашборда профиля — из `env OPENCODE_SCHEDULER_PORT` > `profile.json` > дефолт (3782/4782/5782).

- RPC: `get_profiles`, `set_profile`, `create_profile`, `delete_profile`; дашборд показывает имя профиля в заголовке и в `/api/health`.

### Workspace env (Спринт 21)

- Env-переменные на workspace: `.env`-файл (`envFile`) или пары ключ-значение (`env`); пары переопределяют файл. Валидация имён ключей (`^[A-Za-z_][A-Za-z0-9_]*$`), максимум 100 пар.
- Файл `<PLUGIN_DIR>/env/<sanitized>.env` (права 0600) передаётся обёрткам: Windows — `-EnvFile "<путь>"`, POSIX — `ENV_FILE=` + `set -a; . "$ENV_FILE"; set +a` перед запуском `opencode run`. Значения не попадают в логи: секретные ключи (Token/Secret/Pass/Password/Key/Credential/Auth) маскируются как `***`.

## [1.0.0] - 2026-11-13

First public release.

### Added

- **Scheduling:** cron expressions registered with the native OS scheduler (Windows Task Scheduler, launchd, crontab), pause/resume, timeouts with hard kill, retries with delay, lock-file no-overlap protection.
- **Quality and lifecycle:** Quality Gate command, before/after scripts, allowed/denied tool lists, crash recovery for interrupted runs.
- **Orchestration:** `dependsOn` DAG, `nextTaskOnSuccess` / `nextTaskOnError` chains, file and MCP event triggers.
- **Matrix builds:** fan-out into `<parent>-matrix-<workspace>` clones, parallel/sequential strategies, `continue`/`stop` failure modes, per-matrix concurrency, per-workspace overrides, aggregator task, family sync on edit, cascade delete, cancel, orphan cleanup, `partial` status.
- **Workspaces:** multi-repo registry with path validation, per-task working directory and tool scoping.
- **Observability:** SQLite history and metrics, per-task logs, local web dashboard with pipeline view, matrix grouping and workspace summaries.
- **Operations:** dry-run preview, export/import JSON, templates, webhook notifications, settings.
- **Interfaces:** OpenCode sidebar GUI, web dashboard, agent tools `schedule_task`, `list_tasks`, `delete_task`, `run_task_now`.
- **Cross-platform:** scheduler abstraction with Windows, Linux and macOS backends.

### Known limitations

- Matrix parents are started by `runMatrix()` / DAG only; they are not cron-scheduled.
- Deleting a matrix parent deletes its family, but deleting a workspace does not touch existing matrix jobs.
- Agent tools cover a subset of the RPC surface (see roadmap item 0.4).
