# 🎯 Стратегический роадмап — agent-steward

> Цель: **стать лучшим фреймворком по работе с агентами — супервизором для OpenCode и других харнессов, оставаясь бесплатным и open source.**  
> North Star: [docs/CONCEPT.md](./docs/CONCEPT.md) — верифицируемая локально-первая оркестрация агент-задач.  
> Тактический спринт-план — в [ROADMAP.md](./ROADMAP.md), выпущенные изменения — в [CHANGELOG.md](./CHANGELOG.md).

---

## Позиционирование

**Мы не «cron для OpenCode». Мы не «плагин-планировщик».**  
Scheduler, уведомления, аналитика — триггеры и обвязка, не ядро (CONCEPT §8).

Мы — **локальная платформа оркестрации AI-задач**: расписание + зависимости (DAG) + матрицы (fan-out) + политики качества + наблюдаемость + объективный гейт + learning-loop.

| Принцип | Что это значит на практике |
|---------|---------------------------|
| **Бесплатно навсегда** | MIT, без SaaS, без облачной телеметрии (локальный учёт токенов/запусков — есть), без «pro»-функций |
| **Локально по умолчанию** | Control plane, данные, история, логи, аудит — на машине пользователя |
| **Open source-first** | Публичный roadmap, CI на 3 ОС, английская документация |
| **Оркестрация, а не таймер** | Ров — DAG, матрицы, Quality Gates, наблюдаемость. Cron скопируют за неделю |

## Решение 24.11.2026: стратегический клин

Три варианта из внешнего анализа — не конкуренты, а три входа в одну дверь. Разница лишь в том, где стоит пользователь: в репозитории, в GUI или в чужом агенте.

| Вариант | Что уже есть | Почему не отдельный путь | Куда ведёт |
|---------|--------------|--------------------------|------------|
| GitOps для AI-агентов | pipeline-as-code, CLI `validate/apply/export`, 0.0.5 | Уже сдан; дальше — только Spec (S-1) и CLI-алиас (P-2.3) | Язык описания запусков |
| Локальный Control Plane | GUI, DAG, durable runs, RPC, budgets | Требует того же слоя исполнения; без него — дашборд над cron | P-1 → P-3, `AgentInvoker` |
| MCP-нативный оркестратор | Реестр инструментов, subpath exports в dev-линии | Это дистрибуция ядра, а не ядро; без гейта/учёта — просто MCP-сервер | P-2, `agent-steward mcp` |

**Выбор:** P-1 (изоляция ядра) → P-2 (MCP-адаптер, ~80% ценности) → P-3 (универсальный `harness`), P-4/P-5 в бэклог P3. Суть — `agent-steward/core`: объективный hard-гейт, savings-ledger, capability-роутинг с `first_pass_rate` и flywheel. Дистрибуция — `agent-steward mcp` + subpath exports. Детали и новые ставки — [ROADMAP.md](./ROADMAP.md), детали 3.18/3.19.

## Стратегия развития: от плагина к фреймворку (CONCEPT §13)

Наша эволюция строится на двух столпах и постепенной абстракции.

### Этап 1: глубокая интеграция с OpenCode V1 и V2 (текущий, завершён milestone Д7)

Один пакет, dual export, общее ядро `createRuntime`. V1 и V2 работают через один и тот же пакет с разными ключами конфига (`plugin` для V1, `plugins` для V2).

Статус: ✅ завершён — `agent-steward@0.0.2` опубликован, старый пакет остаётся как `legacy/` (thin re-export на один major).

### Этап 2: абстракция слоя исполнения (Agent Executor Interface)

Вынести интерфейс исполнителя агента за пределы OpenCode-specific кода. Позволить запускать задачи не только через OpenCode, но и через других агентов / MCP / стандартные API.

Спринт 38 (Approvals, окружения, артефакты) закрыт: A-1/A-2/A-3/A-5 реализованы и зафиксированы в CHANGELOG; A-4 — runbook docs-сайта (деплой внешним действием). Спринты 32 (Pipeline-as-code) и 36 (Durable DAG) выпущены в 0.0.5 / 0.0.3–0.0.4 (см. CHANGELOG). Абстракция исполнителя остаётся частичной: `runner*.ts` подключены к execution-пути через слой `AgentInvoker` (P-3.2, fail-open на `local`), `agents*.ts` остаются реэкспортом из `execution.ts` с opt-in политиками; пользовательской настройки runner в схеме задачи пока нет (см. DS-4 в ARCHITECTURE.md).

Конкретные шаги (P-1…P-5) — в [ROADMAP.md](./ROADMAP.md), Деталь 3.9: изоляция ядра → MCP-адаптер (`agent-steward mcp`, ~80% ценности) → `AgentInvoker` + поле `harness` → нативный dsh-плагин → `agent-steward serve`. Один пакет с subpath exports `./core` / `./mcp` / `./dsh`, без монорепо. Экосистема 2026: Cursor / VS Code / IDEA — MCP-клиенты (IDEA — встроенный MCP Server с 2025.2), DeepSeek Harness — Cordis-платформа (`ctx.tools` / `ctx.jobs`, developer preview), ACP — в первую очередь транспорт исполнения. Адаптер OpenCode остаётся неизменным, dual-export V1/V2 не ломается.

Приоритет 24.11.2026: сначала закрыть изоляцию ядра (P-1), затем MCP-адаптер (P-2), затем универсальный `harness` (P-3); P-4/P-5 — бэклог P3. Конкретные задачи — [ROADMAP.md](./ROADMAP.md), детали 3.18/3.19.

### Этап 3: универсальный фреймворк оркестрации (долгосрочно, 0.2.x+)

Универсальный фреймворк, совместимый с любым агентом через MCP или стандартные API. Контекстные артефакты, роли (worker → reviewer), self-correcting retry, model fallback chain, A/B tournament, CEP, входящие внешние события, cross-run memory.

Планируемые спринты: 40–47 (Context artifacts, Crew / роли, Self-correcting retry, Model fallback, Tournament, CEP, входящие события, Cross-run memory, Smart recipes).

## Ров, который не скопируют за неделю

1. **Windows-супервизия.** Конкурент `opencode-scheduler` прямо предупреждает, что на Windows не гарантирует no-overlap и таймауты; у нас обёртки, lock-файлы, crash recovery и единая модель на трёх ОС.
2. **OpenCode v2.** Часть плагинов всё ещё на устаревшем конфиге `plugin` и не подтверждает совместимость с v2.
3. **Оркестрация.** DAG, матрицы, Quality Gates, `partial`-статусы, dry-run и история — этого нет ни у одного планировщика экосистемы.
4. **Локальность.** Никаких облаков и аккаунтов — конкуренты с SaaS-моделью сюда не пойдут.
5. **Learning-loop.** Capability-карта + gate-passed датасет + staged LoRA-адаптеры — персональная компандующаяся capability, которой нет ни у облака, ни у OpenCode core, ни у swarm-фреймворков.

**Чего не делаем:** свой sandbox, свою CI-платформу, хостинг агентов, платные тарифы, open-ended AGI-swarm (CONCEPT §8).

## Долгосрочное видение

Путь от плагина к фреймворку описан в [docs/CONCEPT.md](./docs/CONCEPT.md) (§13): локальный интеллект + мультиагентная оркестрация + абстракция слоя исполнения. Этот тактический роадмап является реализацией Этапа 1 (глубокая интеграция с OpenCode v2) и подготовки к Этапу 2 (абстракция Agent Executor Interface).
