# 🎯 Стратегический роадмап — opencode-windows-scheduler

> Цель: **стать лучшим планировщиком и оркестратором для OpenCode, оставаясь бесплатным и open source.**
> Тактический спринт-план — в [ROADMAP.md](./ROADMAP.md), выпущенные изменения — в [CHANGELOG.md](./CHANGELOG.md).

---

## Позиционирование

**Мы не «cron для OpenCode». Мы — локальная платформа оркестрации AI-задач:**
расписание + зависимости (DAG) + матрицы (fan-out) + политики качества + наблюдаемость.

| Принцип | Что это значит на практике |
|---|---|
| **Бесплатно навсегда** | MIT, без SaaS, без телеметрии, без «pro»-функций |
| **Локально по умолчанию** | Данные, история и логи — на машине пользователя |
| **Open source-first** | Публичный roadmap, CI на 3 ОС, английская документация |
| **Оркестрация, а не таймер** | Ров — DAG, матрицы, Quality Gates, наблюдаемость. Cron скопируют за неделю |

**Текущая точка (1.5.3):**

- опубликован в npm, CI зелёный на Windows / macOS / Linux;
- 25 инструментов агента — паритет с RPC-поверхностью;
- локальный триаж + shadow mode, `manage_local_ai` инструмент + блок настроек в GUI — есть;
- один-shot запуски, непрерывность сессий, профили, webhooks, Telegram и нативные toast, тихие часы, Prometheus и OTLP — есть;
- зашифрованные секреты (${secret:NAME}) и журнал аудита — есть;
- английский README и `docs/` — основные, русский синхронизирован в `docs/README.ru.md`.

**Чего ещё нет:** pipeline-as-code, Docker-runner, approvals и remote runners.

## Горизонт 0–1 месяц: доверие и тишина

Сделано: уведомления (1.3.0), секреты и аудит (1.4.0), git-триггеры и окна (1.5.0).

### 1. i18n-фундамент (P1) — 1.5.1

Все пользовательские строки в `locales/en.json` + `locales/ru.json`, ICU-подмножество на `Intl.PluralRules`, паритет ключей в CI, RU по умолчанию. Без этого нельзя масштабировать аудиторию.

### 2. Security slice A (P1) — 1.5.2

Enforced `allowedTools` / `deniedTools` вместо advisory, scoped-инъекция `${secret:NAME}`, аудит `tool.blocked`. До запуска флагмана приватности: обещание не должно расходиться с реализацией.

### 3. Локальный помощник v1 (P1) — 1.5.3

Триаж уведомлений локальной моделью с fail-open на правила, shadow mode 14 дней, `manage_local_ai`, bench. Меньше шума без потери важного — и работает без модели.

## Горизонт 2–4 месяца: CI/CD-оркестрация

### 4. Локальный помощник v2 (P2) — 1.5.4

Саммари логов в 3 строки, дедуп на эмбеддингах, GUI-wizard, счётчик экономии с пометкой «оценка».

### 5. Pipeline-as-code (P2) — 1.5.5

`opencode.pipeline.yaml` в репозитории + CLI `opencode pipeline validate|run|export`. DAG, матрицы и Quality Gates описываются файлом, который можно ревьюить в PR.

**Почему:** это водораздел между «планировщиком» и «оркестратором». Ни один плагин экосистемы пока не умеет pipeline-as-code.

### 6. Worktree-изоляция и guard-условия (P2) — 1.5.6

Одноразовый `git worktree` на запуск, политика очистки, shell- и семантические guard-условия, статус `skipped`. 80% ценности безопасного fan-out без инфраструктуры Docker.

### 7. Экономика v2 (P2) — 1.5.7

Бюджеты на день/неделю с авто-паузой и алертом, per-task token budgets, token efficiency score, прогноз, Grafana JSON, local vs cloud.

### 8. Docker runner (P3) — 1.5.8

Локальный процесс, Docker, SSH-хост. Задача описывает *что* делать, runner — *где*. Изоляцию не изобретаем: Docker / Landstrip. Opt-in, по умолчанию выключен.

### 9. Durable DAG (P1 для 1.6.0) — 1.5.9

Персистентная state-машина прогона, resume после краша, идемпотентные шаги, DLQ, chaos `kill -9` в nightly.

### 10. Rename-only + daemon + config v2 (P2) — 1.5.10

Переименование в `opencode-pipeline` отдельным релизом без фич (старый пакет живой), `scheduler.backend: native|daemon|off|auto`, автомиграция конфига.

### 11. Approvals, окружения, артефакты (MAJOR) — 1.6.0

Ручное подтверждение перед деплоем, dev / staging / prod, отчёты и coverage как артефакты запуска, docs-сайт и 4 локали.

### 12. Remote runners (P3)

Агент на удалённой машине, центральный дашборд, очередь и конкурентность на кластере. Делать после подтверждения спроса.

## Ров, который не скопируют за неделю

1. **Windows-супервизия.** Конкурент `opencode-scheduler` прямо предупреждает, что на Windows не гарантирует no-overlap и таймауты; у нас обёртки, lock-файлы, crash recovery и единая модель на трёх ОС.
2. **OpenCode v2.** Часть плагинов всё ещё на устаревшем конфиге `plugin` и не подтверждает совместимость с v2.
3. **Оркестрация.** DAG, матрицы, Quality Gates, `partial`-статусы, dry-run и история — этого нет ни у одного планировщика экосистемы.
4. **Локальность.** Никаких облаков и аккаунтов — конкуренты с SaaS-моделью сюда не пойдут.

**Чего не делаем:** свой sandbox, свою CI-платформу, хостинг агентов, платные тарифы.

## Риски и триггеры пересмотра

| Риск | Триггер | Ответ |
|---|---|---|
| Нативный scheduler OpenCode поглощает cron | Стабильный API расписаний | Режим `nativeScheduler`, акцент на DAG / матрицы / политики |
| Похожий плагин с GUI и CI/CD | Релиз конкурента | Ускорить pipeline-as-code и Docker runner |
| Bus factor = 1 | >5 issues без ответа | Сузить scope, заморозить P3, искать мейнтейнеров |
| API OpenCode v2 меняется | Breaking change в `@opencode/plugin` | Держать адаптер, следить за релизами, CI ловит первым |
| Расползание scope | Спринт длиннее 2 недель | Резать на вертикальные срезы, P3 — в бэклог |

## Ближайшие две недели

1. i18n-фундамент (1.5.1) — каталоги локалей, паритет ключей в CI, RU по умолчанию.
2. Security slice A (1.5.2) — спайк по правам агента, затем enforced `allowedTools` / `deniedTools`.
3. Docker runner — после подтверждения спроса.

**Критерий месяца:** пользователь ставит плагин одной командой, получает уведомление в Telegram о падении задачи, токены и доступы не лежат открытым текстом в `tasks.json`, а интерфейс говорит на его языке.
