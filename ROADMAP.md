# 🗺️ Roadmap — agent-steward

> North Star: [docs/CONCEPT.md](./docs/CONCEPT.md) — верифицируемая локально-первая оркестрация агент-задач.
> Это не «планировщик». Планировщик/уведомления/аналитика — триггеры и обвязка, не ядро (§8 CONCEPT).
>
> Модель работы — канбан. Каждая задача разложена слоями:
> **Деталь** (подсистема/файлы) → **Задача** (что чиним/делаем) → **Подзадача** (атомарный шаг).
> В работу берётся ровно одна подзадача: подзадача → отчёт → следующая подзадача.
>
> **В ROADMAP только открытые задачи.** Закрытые задачи и подзадачи удаляются отсюда
> и фиксируются в [CHANGELOG.md](./CHANGELOG.md) — больше нигде.

**Задача QA-A2 — Полная типизация плагина (эпик)** · P3 · ⬜

> Цель: **0 предупреждений** `no-explicit-any` / `no-unsafe-*` в `src/**/*.ts` при 0 ошибок `tsc` и без изменения поведения. На старте 826 предупреждений: ~200 корневых `any` и ~600 каскадных. Оценка — ~1,5–2 недели одному разработчику, знакомому с кодом. Релиз не блокируется: правила в eslint — `warn`, CI уже зелёный.

**Правила выполнения (обязательны для агента):**

1. **НЕ применять `eslint --fix`** — проверено: число предупреждений растёт до 7990 из-за каскада новых `no-unsafe-*`. Только ручная правка.
2. Сначала устраняется **корневой `any`**, затем перепроверяется файл: каскад `no-unsafe-*` уходит сам. Счётчик смотреть через `npx eslint src/<file>.ts --format json`.
3. Стратегия типов: `unknown` + type guard, `z.infer<typeof schema>` из уже объявленных Zod-схем, доменный тип в `src/types.ts` или рядом с модулем. **Запрещено:** `as any`, `@ts-ignore`, новые `eslint-disable` без обоснования. Исключение — границы внешних API (`@opencode/plugin` V1/V2, `node:sqlite`, JSON-пейлоады): disable допустим только с комментарием «почему» и ссылкой на задачу.
4. После каждого файла: `npm run build` + `npx eslint <file>` (счётчик строго снижается) + точечный `npm run test:<имя>` затронутой детали. В конце — полный `npm test`.
5. **Один файл = один коммит** `type(scope): description` латиницей. Поведение не меняется → CHANGELOG не трогать, отмечать только подзадачи здесь.
6. Не редактировать `dist/`, `gui-experimental.cjs`, `legacy/`.

# 2. Задачи согласно архитектуре (Execution model)

agent-steward — execution engine с опциональной регистрацией триггеров. Четыре входа ведут в один путь исполнения; планировщик ОС — только полоса A (cron/once), а не центральный маршрут. Оркестрация (цепочки, DAG, ретраи, матрицы, эскалации) выполняется ядром и рекордером прямыми запусками обёрток.

> Здесь — только открытая архитектурная очередь 0.2.0, структурированная по правилу «деталь → задача → подзадача». Реализованные части execution model перенесены в [CHANGELOG.md](./CHANGELOG.md); описание целевого кровотока — в [docs/EXECUTION-LOOP.md](./docs/EXECUTION-LOOP.md).

> Все задачи ARCH-1..ARCH-7 закрыты и перенесены в [CHANGELOG.md](./CHANGELOG.md). Связанная задача `A-1 — R2/R3 approval-гейт` остаётся открытой в §3: ядро одобрений из ARCH-7 уже есть, но интеграция с GUI/RPC ещё не сделана.

# 4. Правила работы (канбан)

1. **Одна подзадача за раз.** Взял → сделал → отчёт → следующая подзадача.
2. **Слой не пропускается.** Деталь → задача → подзадача; подзадача закрывается только с тестом и документацией.
3. **Закрытое уходит из ROADMAP.** Выполненная задача/подзадача удаляется отсюда и попадает в CHANGELOG.
4. **Нет спринтов.** Статусы ⬜ → 🔄 → ✅ независимо от релизов.
5. **Версия — следствие релиза, а не обещание.** `npm version` в момент релиза.
6. **Приоритет — по боли пользователя.** P1 = без этого нельзя рекомендовать плагин.
7. **Fail-open по умолчанию.** Необязательная подсистема при отказе деградирует, а не блокирует.
8. **Сверка с CONCEPT.md.** Четыре столпа (§4), без противоречий §8.
9. **Честность в маркетинге.** Оценки — с методикой рядом.
