## 2. Четыре столпа (north star, CONCEPT §4)

Любая фича / ADR сверяется с ними. При конфликте порядок: **надёжно > приватно > дёшево > краткосрочные фичи**.

| Столп | Что значит | Метрика |
|-------|-----------|---------|
| **Дёшево** | Локаль закрывает максимум gate-able задач | net-экономия $ (контрфактика), local share %, escalation rate, time overhead |
| **Приватно** | Control plane, данные, аудит, triage — локальны | % инференса/данных локально; cloud-egress только explicit и залогирован |
| **Надёжно** | Ноль тихих отказов / двойных прогонов / fake-done / порчи репо | trust-инциденты = 0; гейт независим от self-report; полнота аудита |
| **Компаундится** | Success rate и экономия растут под пользователя | Тренд local success_rate ↑, eval-lift адаптеров, рост scaffolding-библиотеки |

## 3. Исполнительный цикл (CONCEPT §6)

```
1. Принять миссию + критерий приёмки (гейт)
   ↓
2. Декомпозиция на шаги / роли
   ↓
3. Выбрать исполнителя (локаль first по capability-карте)
   ↓
4. Выполнить шаг (OpenCode-агент)
   ↓
5. GATE — объективная верификация (tests / lint / schema / diff / cmd)
   ├─ pass → ledger: économie + пример + training-record
   └─ fail → эскалация / ретрай / откат
   ↓
6. Артефакт миссии (diff / PR / отчёт / аудит-трейл)
   ↓
7. Отчёт:'économie, success rate, эскалации, overhead
   ↓
8. Обновить роутинг / capability-карту → eval → LoRA (staged)
```

GATE — keystone (§5 CONCEPT): никогда «готово» на слово агента. Провал → эскалация / ретрай / откат.

## 6. Правила планирования

1. **Одна задача за раз.** Внутри спринта не начинаем следующую, пока текущая не закрыта тестом и документацией.
2. **Никаких переименований и миграций внутри функциональных релизов.** Отдельный релиз = отдельный риск.
3. **Каждая фича — с тестом и документацией.** Без этого задача и спринт не закрыты.
4. **Приоритет — по боли пользователя, а не по красоте темы.** P1 = без этого нельзя рекомендовать плагин.
5. **Fail-open по умолчанию.** Любая необязательная подсистема при отказе деградирует, а не блокирует планировщик.
6. **Честность в маркетинге.** «Сэкономлено $» — оценка контрфактики, а не факт. Методика публикуется рядом с цифрой (`docs/SAVINGS.md`).
7. **Сверка с CONCEPT.md.** Любая фича / ADR проверяется на соответствие четырём столпам (§4 CONCEPT) и не противоречит §8 (границы).

## 7. После 0.1.0 — мульти-агентная оркестрация (кандидаты 0.2.x+)

Оценка идей: контекстные артефакты → роли (worker → reviewer) → self-correcting retry → model fallback chain → A/B tournament → CEP → входящие внешние события → cross-run memory. Все возможности **opt-in**; планировщик и базовые задачи обязаны работать без локальной модели, без Docker и без внешних сервисов.

Подробное описание спринтов 40–47 (Context artifacts, Crew / роли, Self-correcting retry, Model fallback, Tournament, CEP, входящие события, Cross-run memory, Smart recipes) — в разделе «После 1.6.0» предыдущей версииroadmap, перенесено в бэклог под новые номера версий 0.2.x+.
