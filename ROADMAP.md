# 🗺️ Roadmap — agent-steward

> North Star: [docs/CONCEPT.md](./docs/CONCEPT.md) — верифицируемая локально-первая оркестрация агент-задач.
> Это не «планировщик». Планировщик/уведомления/аналитика — триггеры и обвязка, не ядро (§8 CONCEPT).
>
> Модель работы — канбан. Каждая задача разложена слоями:
> **Деталь** (подсистема/файлы) → **Задача** (что чиним/делаем) → **Подзадача** (атомарный шаг).
> В работу берётся ровно одна подзадача: подзадача → отчёт → следующая подзадача.
>
> **В ROADMAP только открытые задачи.** Закрытые задачи и подзадачи удаляются отсюда
> и фиксируются в [CHANGELOG.md](./CHANGELOG.md) — больше нигде.
>
> **Нумерация.** Нумерация сохранена для преемственности ссылок: открытые детали —
> 3.15, 3.16 и новая стратегическая 3.19; следующий раздел — 4.

Текущая версия: **agent-steward 0.0.7** (24.11.2026).
Legacy: `opencode-windows-scheduler@1.5.9`.

- Стратегия и позиционирование — [ROADMAP-STRATEGY.md](./ROADMAP-STRATEGY.md).
- Что уже сделано — [CHANGELOG.md](./CHANGELOG.md).
- Устройство и возможности — [docs/ARCHITECTURE.md](./docs/ARCHITECTURE.md), [docs/FEATURES.md](./docs/FEATURES.md).

Обозначения: ⬜ не начато · 🔄 в работе · ⏸️ внешнее действие.

## QA-находки (проверка работоспособности плагина 24.11.2026)

- QA-D316-3: валидация SCOPE для задачи без `workingDirectory` проверяет пути относительно папки сессии, а не репозитория: `update_task` для TPS-1.2 с путями `TEST-PLAN.md` отклонил правку «PL-79/PL-82: SCOPE содержит несуществующие пути», хотя файл есть в `tp-audit-dev`; с префиксом `tp-audit-dev/...` всё проходит — P2. Действие: в сообщении об ошибке явно указывать базовую папку проверки и показывать expect path. Обнаружено 24.11.2026.

- QA-D316-4: на Windows плагин генерирует `.cmd`-обёртки для `qualityGate`/`afterScript` и вставляет тело скрипта в обёртку как есть; `cmd.exe` не понимает PowerShell-синтаксис, поэтому гейт TPS-1.1 упал с `'$r' is not recognized as an internal or external command`, а afterScript — с `& was unexpected at this time`, хотя файлы задачи были записаны — P1. Действие: генерировать `.ps1` или автоматически префиксовать строки `powershell -NoProfile -ExecutionPolicy Bypass -Command ...` / `-File ...`; обход в текущих задачах — вручную добавить такой префикс (проверено: exit 0 и маркер создаётся). Обнаружено 24.11.2026.

- QA-D316-5: watchdog PL-134 завершил запуск TPS-1.1 по «простою 60 с, лог и CPU без изменений» в момент финализации агента: отчёт, правки ROADMAP/CHANGELOG уже были на диске, но прогон помечен `error`, quality gate и коммит не выполнились — P2. Действие: настраиваемый таймаут простоя/grace period и статус `partial` с сохранёнными артефактами вместо жёсткого `error`. Обнаружено 24.11.2026.
- QA-D316-6: при провале quality gate в историю и лог задачи попадает только «Quality Gate провален. Код возврата: 1» — без stdout/stderr самого гейта; пришлось вручную повторять проверки PowerShell, чтобы найти причину (ошибка на единицу в счётчике ссылок и неверная проверка 🔄-суррогата через `[char]0x1F504`) — P2. Действие: включать вывод гейта в `get_history`/`get_task_logs` и, желательно, валидировать скрипт гейта при сохранении задачи. Обнаружено 24.11.2026.
- QA-D316-7: после срабатывания триггера `once` запись остаётся в `list_tasks`, но задание планировщика Windows исчезает, и повторный `run_task_now` падает с `schtasks /run ... ОШИБКА: Не удается найти указанный файл` — P1. Действие: пересоздавать задание планировщика в `run_task_now` (или явно сообщать, что задачу нужно пересоздать через `schedule_task`); обход — повторный `update_task`, который заново регистрирует задание. Обнаружено 24.11.2026.

- QA-D316-8: `run_task_now` возвращает `{success: true, message: "Задача ... запущена."}`, хотя запуск фактически пропущен: `get_history` показывает status `skipped` и `PL-121: в чек-ауте ... уже идёт другая задача — запуск пропущен`. Воспроизведено при запуске D316-TPS1-close-OS, пока чек-аут tp-audit-dev удерживал параллельную задачу QA-D319-2-packaging-OS — P2. Действие: возвращать `success: false` и причину пропуска в ответе `run_task_now`, чтобы вызывающий мог среагировать. Обнаружено 25.11.2026.

- QA-D316-9: `dry_run` с именем несуществующей задачи не возвращает структурированный ответ — через Code Mode падает ошибка «Tool result declared output without an output schema», тогда как `dry_run({})` нормально возвращает 150 задач — P2. Действие: возвращать `{success: false, message: "задача не найдена"}` для неизвестного имени вместо пустого результата, ломающего клиент. Обнаружено 25.11.2026.

- QA-D316-10: watchdog PL-134 прервал агента по «простою 60 с, лог и CPU без изменений» в момент финализации, при этом работа выполнена не полностью: CHANGELOG и `reports/d316-tps1-closed.txt` записаны, но строка TPS-1 из `ROADMAP.md` не удалена. # 4. Правила работы (канбан)

1. **Одна подзадача за раз.** Взял → сделал → отчёт → следующая подзадача.
2. **Слой не пропускается.** Деталь → задача → подзадача; подзадача закрывается только с тестом и документацией.
3. **Закрытое уходит из ROADMAP.** Выполненная задача/подзадача удаляется отсюда и попадает в CHANGELOG.
4. **Нет спринтов.** Статусы ⬜ → 🔄 → ✅ независимо от релизов.
5. **Версия — следствие релиза, а не обещание.** `npm version` в момент релиза.
6. **Приоритет — по боли пользователя.** P1 = без этого нельзя рекомендовать плагин.
7. **Fail-open по умолчанию.** Необязательная подсистема при отказе деградирует, а не блокирует.
8. **Сверка с CONCEPT.md.** Четыре столпа (§4), без противоречий §8.
9. **Честность в маркетинге.** Оценки — с методикой рядом.
