## План 1.6.0 → 2.0.0

План собран 14.11.2026 после выпуска 1.5.0: 11 релизов от i18n-фундамента до 2.0.0. Порядок отражает приоритет по боли пользователя, а не по красоте темы. Каждый спринт — один вертикальный срез не длиннее двух недель.

### Принципы планирования

1. **Один спринт = один вертикальный срез ≤ 2 недель.** Если не влезает — режем, а не растягиваем.
2. **Никаких переименований и миграций внутри функциональных релизов.** Отдельный релиз = отдельный риск.
3. **Каждая фича приходит с тестом и документацией.** Без этого спринт не закрыт.
4. **Приоритет — по боли пользователя, а не по красоте темы.** P1 = без этого нельзя рекомендовать плагин.
5. **Fail-open по умолчанию.** Любая необязательная подсистема (локальный ИИ, Docker, daemon) при отказе деградирует, а не блокирует планировщик.
6. **Честность в маркетинге.** «Сэкономлено $» — оценка контрфактики, а не факт. Методика публикуется рядом с цифрой.

### Спринт 28 — i18n-фундамент (1.6.0, P1)

**Цель:** вынести все пользовательские строки в каталоги и не дать им разъехаться.

**Объём:**
- Каталоги `locales/en.json` + `locales/ru.json`, загрузчик с fallback.
- Экстракция строк: GUI (`gui.tsx`), сервер (`server.ts`), уведомления, сообщения dry-run, ошибки инструментов.
- ICU-подмножество на встроенном `Intl.PluralRules` (без зависимостей): `{count, plural, one/few/many/other}`. Для русского обязательны `one/few/many`.
- Целые фразы-шаблоны, без конкатенации — иначе TR/ZH разваливаются.
- **RU остаётся локалью по умолчанию** (см. риск ниже).
- CI-тест паритета ключей в `test-docs.mjs`: нет ключа → красный CI.
- Резерв имени npm: `opencode-pipeline` заглушкой **в день старта спринта** (см. «Немедленные действия»).

**Вне объёма:** перевод на zh/tr, docs-сайт, bench, рецепт Ollama (переносим в 30).

**Готово, когда:**
- CI падает при рассинхроне локалей (проверено намеренной поломкой);
- `npm run build`, `build:gui`, все 32+ сюита зелёные;
- ни одного пользовательского литерала вне каталога в GUI/уведомлениях;
- переключение локали меняет язык без перезапуска.

**Риски:**
- **Тесты ассертят русские строки** (`«Прервано (сбой/перезагрузка)»`, сообщения dry-run, заголовки в docs-тестах). Миграция: ассерты переводим на ключи или на локаль-независимые идентификаторы. Это отдельная задача внутри спринта, её нельзя «забыть».
- Описания агентных инструментов и API **остаются EN** — это уже так, тест это фиксирует.

### Спринт 29 — Security slice A (1.7.0, P1)

**Цель:** закрыть разрыв между обещанием и реальностью до запуска флагмана.

**Объём:**
- **Спайк (2 дня):** проверить, что `@opencode/plugin` позволяет задавать permission-конфиг на запуск. Если нет — блокировка на уровне обёртки + честная документация ограничения.
- Enforced `allowedTools` / `deniedTools`: обёртка генерирует конфиг прав агента.
- Scoped-инъекция секретов: в env попадают только реально используемые `${secret:NAME}`.
- Аудит заблокированных действий в `audit_log`.

**Вне объёма:** worktree-изоляция (спринт 33), Docker.

**Готово, когда:**
- Запрещённый инструмент физически недоступен агенту (тест на попытку обхода);
- задача без ссылок на секреты не получает ни одного секрета в env;
- в аудите видно `tool.blocked` с задачей и инструментом;
- `docs/FEATURES.md` обновлён: advisory → enforced.

### Спринт 30 — ⭐ Local assistant v1: триаж + shadow (1.8.0, P1)

**Цель:** меньше шума в уведомлениях без потери важного. Работает даже без локальной модели.

**Объём:**
- `notifications.triage`: `mode` (`off`/`rules`/`llm`/`auto`), `baseUrl`, `model`, `timeoutMs`, `fallback`.
- Цепочка деградации: **LLM-классификатор → правила → пропустить триаж (fail-open)**.
- Клиент решений **провайдер-агностик**: конфигурируемый endpoint + модель, без хардкода конкретного стороннего проекта. Пресеты — в документации, не в коде.
- Rules-движок как всегда доступный fallback (статус, задача, текст ошибки, стоимость).
- **Shadow mode** (по умолчанию 14 дней): триаж только логирует вердикты, ничего не глушит.
- Отчёт shadow: false-skip, сколько уведомлений было бы подавлено.
- `scripts/bench-local.mjs` v1: tok/s, подбор тира по RAM, **версионированный JSON** (формат фиксируется под краудсорсинг).
- Рецепт «задача целиком на локальной модели» в `references/recipes.md` + docs: модель, `OLLAMA_CONTEXT_LENGTH=65536` как troubleshooting, а не как требование кода.
- Инструмент `manage_local_ai` + минимальный GUI-блок настроек.
- **Спайк:** проверить формат id моделей Ollama в текущей версии OpenCode и надёжность structured output у 4B-моделей.

**Вне объёма:** эмбеддинги, дедуп, саммари, wizard, счётчик экономии (спринт 31).

**Готово, когда:**
- Ollama недоступна → работают правила, уведомления **никогда** не блокируются (тест на таймаут и на отказ соединения);
- shadow-отчёт показывает false-skip и подавленные уведомления;
- ответ модели валидируется по схеме, при невалидном JSON — fallback на правила;
- bench выдаёт стабильный JSON на 16 ГБ CPU-машине;
- порог уверенности настраивается и покрыт тестом.

**Формулировка приёмки (важно):** не «первое саммари < 10 минут после установки» — это зависит от скорости скачивания модели и не контролируется нами. Вместо этого: «установка и работа планировщика не ухудшаются, если локальной модели нет».

### Спринт 33 — Worktree-изоляция + guards (1.11.0, P2)

**Объём:**
- Одноразовый `git worktree` на запуск: политика очистки, защита незакоммиченных изменений, снятие lock-файлов после краша.
- Guard-условия: shell-команда (exit-код) + семантический `guardPrompt` через локальный тир.
- Статус `skipped`, причина в dry-run.

**Готово, когда:** два клона матрицы на одном репозитории не конфликтуют; семантический guard прошёл shadow-проверку; тесты на git/glob/окна/guard.

**Почему раньше Docker:** worktree даёт 80% ценности «безопасный параллельный fan-out на одном репо» без инфраструктуры и без проблем Windows-CI.

### Спринт 36 — Durable DAG (1.14.0, P1 для 2.0)

**Цель:** пережить краш посреди прогона.

**Объём:**
- Персистентная state-машина прогона (шаг → статус → попытка).
- Resume с середины после краша.
- Идемпотентные ключи шагов.
- DLQ для окончательно упавших шагов.
- Chaos-тест `kill -9` посреди DAG в nightly.

**Готово, когда:** `kill -9` посреди DAG → продолжение с того же шага; повторный запуск шага не дублирует побочные эффекты; DLQ видна в GUI.

**Почему отдельно:** это самое сложное изменение ядра за весь план. Оно трогает цикл запуска, схему истории и планировщик. Смешивать его с переименованием нельзя.

### Спринт 37 — Rename-only + daemon + config v2 (1.15.0 → 2.0-rc, P2)

**Часть A — переименование (отдельный коммит/релиз, без фич):**
- Публикация `opencode-pipeline` как тонкого re-export поверх текущего пакета.
- GitHub-переименование с редиректами.
- Trusted publishing на новый пакет.
- **Старый пакет остаётся живым** и продолжает получать патчи. `npm deprecate` — только после того, как новый пакет наберёт сопоставимые загрузки.

**Часть B — daemon:**
- `scheduler.backend: native | daemon | off | auto`.
- daemon: systemd user / launchd agent / Windows-сервис, catch-up политика.
- `off` = чистый событийный оркестратор.

**Часть C — config v2:**
- Автомиграция, `OPENCODE_PIPELINE_*` с fallback на старый префикс.
- Migration guide, проверенный на реальном старом экспорте.

**Готово, когда:** старый пакет работает через обёртку; `off`-режим живёт только на событиях; миграция проверена на старом экспорте; ни одна фича не сломана переименованием.

### Решения по плану (согласованы 14.11.2026)

1. **Security до флагмана — принято.** Enforced `allowedTools` / `deniedTools` выходит в **1.7.0**, до локального помощника. Флагман не может продавать приватность на advisory-правах.
2. **Переименование — зарезервировать сейчас, решать перед 1.15.0.** Имя `opencode-pipeline` резервируется заглушкой в день старта спринта 28. Окончательное решение о переезде принимается перед rename-релизом, по факту загрузок и обратной связи. Аргументы против переезда: «pipeline» сужает продукт (мы — планировщик + оркестратор), ломает установки, требует поддерживать два пакета. Аргументы за: «windows-scheduler» уже неточен (три ОС) и мешает позиционированию.
3. **11 релизов — принято.** Каждый спринт ≤ 2 недель и один вертикальный срез. Слияние 31→30 и 33→32 остаётся аварийным вариантом при нехватке ресурсов, но не планом по умолчанию.
4. **Локальный ИИ — строго опция.** `mode: off` по умолчанию, включение через wizard. Решено на уровне архитектуры, не только документации.
5. **Открыто:** кто владелец locale-файлов (CODEOWNERS) — нужен до 1.9.0, иначе zh/tr будут мертворождёнными.

## Идеи без спринта

- **Remote runners**: агент на удалённой машине, центральный дашборд, очередь и конкурентность на кластере.
- **Экспорт в CI**: адаптеры GitHub Actions и GitLab CI из pipeline-as-code (не наоборот).
- **Библиотека рецептов**: встроенные шаблоны (`nightly-refactor`, `dependency-audit`, `doc-sync`, `coverage-report`) + `manage_templates action=install`.
- **DAG в GUI**: клик по узлу → карточка задачи, zoom/pan, подсветка пути, дорожка матричных клонов.
- **Нативный scheduler OpenCode**: режим `nativeScheduler: auto|on|off` вместо рекомендации отключать `experimental.schedules`.

## Правила разработки

- Node.js 20+ (`engines`), CI — Node 24 на Windows, macOS и Linux.
- Обязательны `npm run build` и `npm run build:gui`; `npm test` включает 32 сюита, включая `test-docs.mjs`.
- Новые runtime-зависимости — только с обоснованием; предпочтение optional dependencies и нативным командам ОС.
- Обратная совместимость: старые `tasks.json` и экспорт читаются без миграции пользователем.
- Каждый релиз обновляет CHANGELOG, README (EN + RU) и `docs/`; устаревшие отчёты спринтов не хранятся в корне — история живёт здесь и в CHANGELOG.
